CHULETA AWS - PALABRAS CLAVE

FLUJO GENERAL
Correo + adjuntos
-> S3: archivos originales
-> RDS: solicitud inicial
-> SQS: mensaje pendiente
-> Worker: procesa
-> RDS: estado y resultados
-> respuesta / registro externo

S3
Almacenamiento de objetos.
Guarda PDF, Excel, Word, correo y resultados grandes.
Conserva los archivos originales.
No extrae ni valida.

RDS
Servicio gestionado de AWS para PostgreSQL o MariaDB.
Tablas como hojas de Excel relacionadas.
Guarda solicitudes, trabajadores, validaciones, registros y auditoría.
AWS gestiona servidor, backups y parches.
Yo gestiono tablas, índices, consultas y permisos.

TABLAS
requests: una fila por solicitud y su estado.
workers: trabajadores de cada solicitud.
validations: errores o incidencias detectadas.
registrations: resultado del registro externo.
audit_events: historial de pasos.
Clave común: solicitud_id.

SQS
Cola de trabajos.
Un mensaje por solicitud.
No guarda normalmente el PDF.
Guarda solicitud_id y referencia a S3.
Reparte trabajo entre workers.
Permite procesar de forma asíncrona.

WORKER
Lee mensaje SQS.
Descarga archivos de S3.
Extrae datos.
Valida documentos y negocio.
Decide.
Actualiza RDS.
Registra si procede.
Genera respuesta.
Confirma SQS al terminar bien.

DESPUÉS DEL WORKER
Éxito:
-> estado registered/completed
-> guardar respuesta API
-> auditoría
-> correo o borrador
-> confirmar mensaje SQS

Revisión humana:
-> estado human_review en RDS
-> bandeja para persona
-> persona aprueba o rechaza

Error técnico:
-> guardar error
-> no confirmar SQS
-> reintento

ESTADOS
received
processing
approved
denied
request_documents
human_review
registered
failed

IDEMPOTENCIA
Mismo mensaje dos veces = una sola inscripción.
Comprobar solicitud_id / cif + accion antes de registrar.

REINTENTOS CON BACKOFF
Fallo -> esperar 1 s -> reintentar.
Fallo -> esperar 2 s -> reintentar.
Fallo -> esperar 4 s -> reintentar.

DEAD-LETTER QUEUE
Cola especial para mensajes que fallan varias veces.
Una persona los revisa después.

RATE LIMITING
Limitar llamadas por segundo.
Evitar saturar la API externa.

UN MILLÓN DE SOLICITUDES
SQS reparte.
Varios workers en paralelo.
Escalar workers según mensajes pendientes.
RDS con índices.
Consultas paginadas.
Procesamiento asíncrono.
Idempotencia y reintentos.

ÍNDICES
Buscar rápido por solicitud_id, cif, accion y estado.
Índice útil: (cif, accion).

PAGINACIÓN
No pedir un millón de filas de golpe.
Consultar bloques: 1-1000, 1001-2000...

SEGURIDAD
S3 privado.
Cifrado en reposo y en tránsito.
Roles IAM con permisos mínimos.
RDS en subred privada.
Secretos en Secrets Manager.
Nunca claves en el código.
Logs sin DNI ni documentos completos.
Retención limitada de datos.

MONITORIZACIÓN
Mensajes pendientes en SQS.
Errores del worker.
Latencia.
Reintentos.
Mensajes en dead-letter queue.
Errores de API externa.
Solicitudes en human_review.
Porcentaje automatizado.

ALERTAS
Cola creciendo demasiado.
Muchos fallos del worker.
API externa caída.
Dead-letter queue con mensajes.
Tiempo de procesamiento alto.

ARQUITECTURA DEL PROYECTO
extract.py: CLI individual.
request_extractor.py: coordina el flujo.
email.py: extrae correo.
pdf.py: extrae PDF / coordina OCR.
ocr.py: Tesseract opcional; fallback a revisión humana.
worker_list.py: Excel o Word.
validation.py: documentos y DNI.
business_validator.py: consultas de negocio.
decision.py: incidencia -> decisión.
responses.py: borrador y refinamiento.
lm_studio.py: conexión con LLM local.
registration.py: simulación / registro real.
api.py: llamadas HTTP a API mock.
batch_processor.py: lote y summary.json.

LLM
Se usa después de la decisión.
Solo mejora asunto y cuerpo.
No aprueba ni deniega.
Plantilla determinista como fallback.
Si falla, se conserva la plantilla.

FRASE FINAL
S3 guarda archivos; RDS guarda estados y resultados; SQS reparte trabajos; workers procesan; RDS se actualiza; se registra si procede; y los fallos se reintentan o van a revisión.
